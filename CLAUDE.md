# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Symfony bundle (`max-shamaev-php/logger-bundle`, namespace `MaxShamaev\LoggerBundle`) that extends Monolog with processors, formatters, an exception-filtering decorator, and a Sentry integration. Requires PHP >= 8.4 and Symfony 6.4 / 7.x / 8.x (`composer.json` is authoritative — note the README still says PHP 8.1 / Symfony 6.4+).

## Commands

All workflows go through the `Makefile`:

- `make test` — run PHPUnit (`vendor/bin/phpunit`). Single test: `vendor/bin/phpunit --filter <TestName>` or `vendor/bin/phpunit tests/unit/Monolog/Formatter/JsonFormatterTest.php`.
- `make test-with-coverage` — HTML coverage report into `coverage/`.
- `make check` — full quality gate: `php -l` on every non-vendor PHP file, PHPStan (level 9, `--memory-limit=512M`), PHP-CS-Fixer in check mode, `composer audit`, and Rector in dry-run (`-n`).
- `make fix` — apply PHP-CS-Fixer and Rector autofixes.
- `make regenerate-baseline` — rewrite `phpstan-baseline.neon` after intentional PHPStan changes.

PHPUnit config is strict (`failOnRisky`, `failOnWarning`, `failOnPhpunitDeprecation`, `beStrictAboutOutputDuringTests`) — silence warnings/output rather than ignoring them.

Rector is configured with `withSymfonyContainerPhp(__DIR__ . '/var/cache/dev/App_KernelDevDebugContainer.php')`. That cache file is not generated by this bundle (no kernel), so Symfony-container-aware rules may be inert when running Rector here standalone — don't try to "fix" the missing file.

## Architecture

The bundle's wiring lives in three places that must stay in sync:

1. **`src/LoggerBundle.php`** registers the extension and the `AddExceptionFilterPass` compiler pass.
2. **`src/Resources/config/services.yaml`** uses `autowire`/`autoconfigure` with a PSR-4 resource scan that **excludes** `Monolog/Processor/` and `Monolog/Handler/` — those are wired explicitly. New processors must be added to the explicit `monolog.processor` tag list there; new handlers/decorators do not autoload via the resource scan.
3. **`src/DependencyInjection/Compiler/AddExceptionFilterPass.php`** walks every service whose id starts with `monolog.logger`, skips abstracts and existing decorators, and wraps each with `ExceptionFilterDecorator`. This is how exception filtering applies to *every* channel without per-channel config.

### Exception filtering flow

`ExceptionFilterDecorator` (in `src/Monolog/Handler/`) is a PSR-3 `LoggerInterface` decorator (not a Monolog handler, despite the directory name). It inspects `$context['exception']`; if it is an instance of any class in `logger_bundle.exception_classes`, the call is silently dropped — *except* for `debug()`, which always passes through. When adding a log level, preserve that asymmetry.

### Formatter pair

`SwitchFormatter` chooses between Symfony's `monolog.formatter.line` (human-readable) and `JsonFormatter` based on `PHP_SAPI === 'cli'` (or no current Request) **and** the `HUMAN_READABLE` env var. `JsonFormatter` extends Monolog's `JsonFormatter` and post-processes the normalized record to:

- Inject `application` / `component` from `logger_bundle.applicationName` / `logger_bundle.componentName` (sourced from `APPLICATION_NAME` / `COMPONENT_NAME` env vars, defaulting to `unknown`).
- Move `count`/`size`/`duration` (kept as int/float) and `id`/`status` (cast to string) out of `context` into a top-level `metrics` object. Empty `context`/`extra`/`metrics` are serialized as `{}` (via `stdClass`) rather than `[]`.

### Context-aware exceptions

`ExceptionContextProcessor` walks the `$context['exception']` chain (`getPrevious()` until cycle-detected via `spl_object_hash`) and merges `getContext()` from any exception implementing `ContextAwareExceptionInterface` into the log record's context. Consumers attach context via `ContextAwareExceptionTrait`.

### Sentry integration

`Sentry\Integration\LoggerIntegration` is **opt-in** — it is *not* autoconfigured into Sentry; users must add it to `sentry.options.integrations`. It is excluded from PHPStan (`phpstan.dist.neon`) and from Rector (`src/Sentry/*` is skipped) because `sentry/sentry` is not a required dependency.

## Testing notes

- Tests live in `tests/unit/` but the dev autoload PSR-4 prefix is `MaxShamaev\HealthCheckBundle\Test\Unit\` — this looks like a copy/paste leftover from another bundle. New tests in this tree should match whatever the existing neighboring files use; don't "correct" the namespace without checking that tests still load.
- There is no Symfony kernel / integration test harness — tests instantiate processors/formatters directly with mocks.
